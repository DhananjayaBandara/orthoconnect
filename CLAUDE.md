## 1. Identity and purpose
**OrthoConnect** — public website for **Dr. Suneth De Silva, Consultant Orthopaedic Surgeon** (Sri Lanka). It introduces the surgeon, publishes bilingual (English/Sinhala) patient education, and **routes patients to hospital booking pages on eChannelling and Doc990**. It does **not** take bookings, collect data, or run a CMS. Brief names `orthoconnect.lk` as the production domain; that string appears nowhere in the repo (documented host: `https://dhananjayabandara.github.io/orthoconnect/`).

## 2. ⚠ The stack is NOT PHP/MySQL
No PHP, SQL, database, server, auth, forms or admin exist. It is a **static site generated by a Python ≥3.12 stdlib script**; generated HTML is committed and served by GitHub Pages (DOCUMENTED). `orthopaedic.lk` = legacy WordPress site the 40 articles were scraped from (internal provenance only; its relationship to this project is an **open question** — see doc 20 OQ-02).

## 3. Architecture in one paragraph
`content/**/*.json` (+ some copy inside `scripts/*.py`) → `python3 -B scripts/build_site.py` validates everything **before writing**, then renders 70 pages (11 public + 3 alias copies + 56 reading pages) → committed → served as-is. Browsers get HTML/CSS plus ~30 KiB of vanilla JS used only for progressive enhancement (menu, filters, carousels). Filter state lives in the URL; no cookies/storage/analytics/third-party requests. Rebuild is deterministic (verified byte-identical).

## 9. Conventions
Python: stdlib only, f-string templates, `e()`/`html.escape` on **every** dynamic value, validate-then-write, `ValueError` with the offending ID. JS: `'use strict'`, `data-*` hooks, progressive enhancement via `hidden`/`.js-enabled`, URL as state, no network/storage. CSS: tokens → kebab-case components, `is-*` states, reduced-motion + print blocks. Content: stable lowercase-hyphen `id`s; text only (no HTML/Markdown); `lang` on foreign passages; unknown = `null`/omitted.

## 10. Hard rules for this repository
1. **Never hand-edit generated `*.html`** — edit sources, rebuild, run the three Python audits, commit sources **and** regenerated HTML together.
2. Keep `status: "draft"` unless a **named reviewer + ISO date** are supplied by the client. Never invent credentials, years, registrations, contacts, fees, schedules, bylines, testimonials, counts or review dates.
3. Don't remove `noindex`, add analytics/cookies/WhatsApp/forms/maps, or change `privacy.html`/`terms.html` claims without client approval and a policy update.
4. Booking links: use the **exact** doctor-and-hospital sessions URLs; don't change Doc990 `/si/`/`/tm/` paths; `check_clinics.py` hard-codes 18 clinics / 8-5-5 provider split — update audit, provenance and docs together.
5. Don't run `import_articles.py --replace` (overwrites drafts, `site.json`, provenance and `docs/article-migration-review.md`). `check_article_migration.py` asserts exactly 40 articles (19/21).
6. Leave supplied logo/portrait/archive images byte-identical. Don't hotlink external assets; keep URLs relative (no root-relative paths).
7. **This repo is canonical**; `../orthoconnect-lk-website/` is a stale copy. `README.md:139` points at it — wrong.
8. GitHub Pages publishes the **entire repo root**. `docs/system-discovery/` and this file would be public if committed — decide the publish boundary first; do not commit the security assessment publicly.
